# 第一批平台与权限服务实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `jeez-foundation` 中新增 `zp-service-platform` 模块，并打通第 1 批平台与权限服务接口，使前端首批基础上下文接口能够基于 `zp_pms` 真实数据联调。

**Architecture:** 采用单服务 `zp-service-platform` 主写平台与权限域表，复用父工程的 Spring Boot 3.1.5、MyBatis-Plus、Sa-Token、`zp-common` 与 `zp-gateway`。接口分两层：服务内部沿用现有 Service/Mapper/Entity 组织；对外针对前端已使用接口增加“前端兼容响应适配层”，优先输出前端当前可解析的 `code=0/data/traceId/timestamp` 结构，而不直接改写 `zp-common.Result` 的全局语义。网关只做路由与认证透传，登录接口在平台服务内签发 Token，鉴权接口依赖网关注入的 `X-User-Id` 等可信头。

**Tech Stack:** Java 17、Spring Boot 3.1.5、Spring Cloud Gateway、MyBatis-Plus、MySQL 8、Redis、Sa-Token、Springdoc OpenAPI、JUnit 5、MockMvc。

## 一、范围与约束

### 1. 本批次只做这些接口

- `POST /auth/login`
- `POST /auth/logout`
- `GET /auth/me`
- `POST /user/own/get`
- `POST /camps/get`
- `POST /camp/get`
- `POST /menus/project/get`
- `POST /menu/optionJsons/get`
- `POST /systemConfigs/get`
- `POST /channels/get`
- `POST /edition/resource/get`

### 2. 本批次主写/主读表

- 用户与成员：`pms_user`、`pms_member`
- 门店与项目：`pms_camp`、`pms_poi`
- 角色权限：`pms_role`、`pms_role_authority`、`authority_dict`、`user_authority_exclude`
- 系统配置：`system_config`、`user_system_config`
- 渠道：`channel_account`、`channel_poi_rel`、`notify_channel_binding`

### 3. 关键兼容原则

- 前端当前对部分接口按 `code === 0` 解析，不能直接返回 `Result.success()` 的 `code=200`。
- `zp-common.Result/PageResult` 仍保留，避免全局破坏；新增平台服务专用响应适配类，仅用于首批前端兼容接口。
- 若数据库没有“版本订阅/菜单 JSON”完整表，本批先返回最小兼容结构，字段必须能让前端页面正常渲染。
- 不改表结构、不引入 mock 数据替代真实查询；只允许对“数据库中不存在但前端强依赖的展示型字段”做受控兼容拼装。

## 三、接口设计基线

### 1. 登录相关

- `POST /auth/login`
  - 入参：`mobile` 或 `email` + `password`（本计划明确采用演示库账号直登：当 `pms_user` 无密码字段时，固定要求 `password=demo-login`，仅做账号存在性校验，并在登录响应中返回 `loginMode=demo-direct`）
  - 出参：
    - `token`
    - `tokenName`
    - `userId`
    - `memberId`
    - `campId`
    - `roleCode`
    - `roleName`
- `POST /auth/logout`
  - 依赖网关透传 Token
- `GET /auth/me`
  - 返回当前登录用户、角色、camp、poi、权限摘要

### 2. 首批上下文接口

- `/user/own/get`
  - 返回当前用户信息、成员信息、默认角色、默认 camp/poi。
- `/camps/get`
  - 至少返回 `camps: [{ campId, name, poiId, poiName }]`。
- `/camp/get`
  - 按 `campId` 返回门店详情；字段至少覆盖 `campId`、`name`、`cityName`、`address`、`contactNumber`。
- `/menus/project/get`
  - 返回前端可用的项目菜单；首版保证能返回 `projectMenuId` 与基础菜单树。
- `/menu/optionJsons/get`
  - 返回 `optionJsonViews[].optionJson.versionModals`，兼容 IM 设置页。
- `/systemConfigs/get`
  - 返回配置列表，字段至少包括 `configKey`、`configValue`。
- `/channels/get`
  - 返回渠道列表，字段至少包括 `channelId`、`channelName`、`accountId`、`poiId`。
- `/edition/resource/get`
  - 返回 `editionId`、`editionName`、`resourceName`、`expireDateRange`、`priceText`、`connectorProgress` 等前端已读取字段。

- [ ] **Step 2: 实现网关可信头校验拦截器**

```java
public class GatewayTrustInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        if (request.getRequestURI().startsWith("/auth/login")) {
            return true;
        }
        String userId = request.getHeader("X-User-Id");
        String verified = request.getHeader("X-Auth-Verified");
        if (!"true".equals(verified) || userId == null || userId.isBlank()) {
            throw new BusinessException(401, "未通过网关认证");
        }
        LoginUserContext.setCurrentUserId(Long.valueOf(userId));
        return true;
    }
}
```

      u.nick_name,

## 五、风险与回避策略

1. **现有工作区很脏**
   - 先不要清理别人已有改动。
   - 执行时优先用独立分支或 worktree。

2. **`Result` 与前端 `code=0` 约定冲突**
   - 不全局改 `zp-common.Result`。
   - 首批平台接口单独走兼容响应类。

3. **数据库没有独立菜单/版本资源表**
   - 菜单 JSON 与版本信息首版返回最小兼容对象。
   - 必须在代码注释与文档中标出“兼容拼装字段”。

4. **登录表缺少密码字段**
   - 首版只做演示库账号直登，错误信息必须清晰，不做假密码校验。
   - 第二批再补密码体系或对接真正认证源。
